# Техническое внедрение правовых документов

Этот файл не публикуется как пользовательский документ. Он описывает
минимальную серверную и мобильную реализацию.

## 1. Публичные маршруты

Документы должны открываться без авторизации:

- `/legal/privacy`;
- `/legal/terms`;
- `/legal/personal-data-consent`;
- `/legal/personal-data-dissemination-consent`.

Контент должен отдаваться по HTTPS с номером версии, датой вступления в силу и
контрольной суммой.

## 2. Модель данных

Реализованная схема создается миграцией
`000047_legal_consents_retention`:

```sql
CREATE TABLE legal_consent (
    id bigserial PRIMARY KEY,
    user_id integer REFERENCES "user"(id) ON DELETE SET NULL,
    registration_id varchar(128),
    document_type varchar(64) NOT NULL,
    document_version varchar(32) NOT NULL,
    document_sha256 char(64) NOT NULL,
    accepted_at timestamptz NOT NULL DEFAULT now(),
    ip_address inet,
    user_agent text,
    app_version varchar(64),
    source varchar(16) NOT NULL CHECK (source IN ('web', 'android')),
    revoked_at timestamptz,
    revocation_reason text,
    CHECK (user_id IS NOT NULL OR registration_id IS NOT NULL)
);

CREATE INDEX legal_consent_user_timeline_idx
    ON legal_consent (user_id, accepted_at DESC);
```

Сервер не принимает текст или hash документа от клиента: действующая версия и
SHA-256 задаются конфигурацией. До подтверждения OTP запись связана с
`registration_id`, после подтверждения — с `user_id`. При отзыве доказательные
поля не изменяются: сервер заполняет только `revoked_at` и причину отзыва.

## 3. Регистрация

До отправки телефона или email пользователь видит ссылки на Политику и
действующую версию документов.

Отдельные действия:

1. Обязательное: «Принимаю Пользовательское соглашение».
2. Отдельное: «Даю согласие на обработку персональных данных» только для целей,
   которые действительно основаны на согласии.
3. Необязательное: рекламные сообщения, выключено по умолчанию.

Нельзя использовать один чекбокс «Продолжая, вы соглашаетесь со всем».

До создания пользователя принятия можно связать с серверным идентификатором
попытки входа, а после подтверждения номера или email атомарно привязать к
`user_id`.

Клиент передает не произвольный текст, а `kind + version`. Сервер самостоятельно
проверяет действующий документ и сохраняет его `content_hash`.

## 4. Первая публикация

Перед первой публикацией объявления или открытием публичного профиля:

1. показать отдельное согласие на распространение;
2. не публиковать телефон, email, дату рождения и текущую геолокацию;
3. только после успешной записи согласия публиковать профиль или объявление.

## 5. Существующие пользователи

После выпуска юридической версии:

- показать блокирующий экран принятия обязательных документов;
- не считать использование старой сборки доказательством согласия;
- не проставлять согласия миграцией за пользователя;
- до отдельного согласия скрыть данные, для которых требуется разрешение на
  распространение;
- сохранить предыдущие версии документов и историю действий.

## 6. Отзыв и удаление

В настройках должны быть отдельные действия:

- отзыв согласия на распространение;
- запрос по персональным данным;
- удаление аккаунта.

Отзыв фиксируется в журнале, скрывает публичный профиль и снимает активные
объявления с публикации. Для юридических обращений используется
`legal@wigaj.ru`.

Отзыв не должен удалять платежные, фискальные или иные записи, которые
обрабатываются на основании закона. Интерфейс обязан объяснять последствия.

## 7. Повторные чекбоксы не нужны

Не нужно повторно спрашивать согласие при каждой заявке, отправке сообщения,
отзыва или фотографии. Для этих операций сервер проверяет действующее
Пользовательское соглашение и применимое основание из Политики.

Новое согласие требуется, если:

- появилась новая несовместимая цель обработки;
- расширился перечень публично распространяемых данных;
- подключен новый рекламный канал;
- закон или новая редакция документа требует нового волеизъявления.

## 8. Проверки перед релизом

- ни один обязательный документ не содержит `{{ПЛЕЙСХОЛДЕР}}`;
- опубликованный hash совпадает с hash, настроенным для `legal_consent`;
- регистрация без обязательного принятия отклоняется сервером;
- согласие на распространение не объединено с другими документами;
- отзыв отражается на публичных DTO и кэше;
- юридические маршруты доступны без аккаунта и из RuStore;
- все времена сохраняются в UTC;
- журнал принятия включен в резервное копирование и аудит доступа.
