# Design system и UI Kit

Sutki UI Kit — внутренний слой интерфейса приложения. Он не зависит от страниц и бизнес-фич и импортируется через `@ui`.

## Принципы

1. **Семантические токены.** Компоненты используют роли (`--surface`, `--ink`, `--accent`, `--border`), а не цвета конкретного экрана.
2. **Один компонент — один контракт.** Бизнес-правила остаются в feature/page, UI-примитив получает только данные и intent-callbacks.
3. **Адаптивность через контекст и CSS.** `UIProvider` управляет плотностью, а `shared/lib/adaptivity` даёт типизированные viewport-хуки для случаев, где CSS недостаточно.
4. **Композиция вместо матриц флагов.** Составные сценарии строятся из `Surface`, `Stack`, `Field`, `DialogActions` и других примитивов.
5. **Доступность по умолчанию.** Нативные элементы, видимый focus, доступные имена icon-only кнопок, управление диалогами с клавиатуры и восстановление фокуса.
6. **Публичный API.** Внешний код импортирует только `@ui`; глубокие импорты блокирует `check:architecture`.
7. **Документированное состояние.** Для нового примитива обязательны story и состояния default/hover/focus/disabled/loading/error, когда они применимы.

## Уровни компонентов

- **Foundations:** tokens, typography, density, themes, motion.
- **Primitives:** Button, TextField, Surface, Badge, Avatar.
- **Compositions:** Field, ListCell, DialogActions, AppHeader.
- **Product patterns:** карточки заявок, строки чатов и карточки объявлений остаются в feature/entity, потому что содержат доменную семантику.
- **Pages:** только композиция сценариев и route-level состояния.

## Когда переносить код в shared/ui

Компонент поднимается в UI Kit только если у него есть минимум два реальных потребителя с одинаковой семантикой, стабильный API и отсутствуют бизнес-правила конкретной фичи. В противном случае компонент остаётся page-local или feature-local.

## Storybook

Storybook использует тот же Vite-конфиг и aliases, глобальные токены, light/dark темы, comfortable/compact density и viewport presets. Полные page stories позволяют проверять экраны без запуска всего приложения.


## Автоматические контракты

`npm run check:ui-kit` проверяет, что каждый корневой компонент в `src/shared/ui`:

- имеет публичный export через `@ui`;
- упомянут в Storybook stories;
- не требует глубокого импорта из продуктового кода.

`npm run check:architecture` дополнительно запрещает зависимости `shared → feature/page/app` и глубокие импорты во внутренности feature/entity/widget.
