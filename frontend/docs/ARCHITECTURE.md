# Архитектура ВИГАЖ Web

Проект организован по слоям с направлением зависимостей:

```text
app
  → pages
    → widgets
      → features
        → entities
          → shared
```

## Слои

- `src/app` — запуск приложения, маршрутизация и композиция глобальных провайдеров.
- `src/screens` — тонкие route-level экраны. В импортах слой сохраняет FSD-алиас `@pages`; у каждого экрана есть публичный `index.ts`, а реализация лежит в `ui/`.
- `src/widgets` — крупные переиспользуемые блоки страниц, например основная навигация.
- `src/features` — пользовательские сценарии и их состояние: поиск, фильтры, чат, заявки, профиль.
- `src/entities` — отображение доменных сущностей, например карточка объявления.
- `src/shared` — UI Kit, токены, инфраструктура, общие утилиты и типы.

## Публичные API

Межслойные импорты выполняются через публичный `index.ts`:

```ts
import { RequestsPage } from '@pages/requests';
import { requestRepository } from '@features/requests';
import { ListingCard } from '@entities/listing';
import { Button, Modal } from '@ui';
```

Глубокие импорты во внутренности другой feature/entity/widget запрещены. Это проверяет:

```bash
npm run check:architecture
```

## Правила размещения

1. Код, используемый только одной страницей, остаётся рядом с этой страницей.
2. Код поднимается в `features`, `entities`, `widgets` или `shared` только при наличии реального повторного использования.
3. `shared` не знает о бизнес-фичах.
4. Страница не импортирует другую страницу.
5. Доступ к данным идёт через repository-контракт, а не напрямую из UI.
6. Session mock и HTTP-адаптеры имеют одинаковый интерфейс и переключаются конфигурацией.

## Маршрутизация

Маршрутизация изолирована в `src/app/router`. `App.tsx` отвечает только за application state и композицию, `AppRouteView` — за сопоставление route contract с экраном, а search/date/guest/filter overlays находятся в `app/ui`. Route-level экраны подключаются синхронно, без общего промежуточного индикатора; состояния загрузки данных принадлежат самим экранам и повторяют их структуру скелетонами. Текущий лёгкий history-router не добавляет внешнюю зависимость и поддерживает deep links; при переходе на React Router публичные API страниц и фич останутся прежними.

## Генераторы

```bash
npm run generate:page -- favorites "Избранное"
npm run generate:ui -- PriceBreakdown
```

Генераторы создают публичный API, компонент и Storybook story в правильном слое.
